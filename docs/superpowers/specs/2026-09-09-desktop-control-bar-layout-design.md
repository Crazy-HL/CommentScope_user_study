# 桌面端顶部控制栏布局优化设计

日期：2026-09-09

## 背景

当前在 1280×720 视口下，顶部控制栏使用从左到右连续排列的 flex 布局。三个控件组结束后，右侧仍有约 270px 空白，导致控制栏视觉重心偏左。

## 目标

仅优化桌面端（视口宽度 `>=1201px`）的顶部控制栏：

- 减少右侧无效空白；
- 保留适度的左右边距，控件不贴近控制栏边缘；
- 让布局切换按钮保持页面视觉中心；
- 不改变任何控件、功能和交互；
- 不改变 `<=1200px` 的现有平板及移动端布局。

## 布局方案

桌面端将 `.control-panel-inner` 调整为三段式 CSS Grid：

1. 左区：评论显示开关，左对齐；
2. 中区：Sentence-End、Between-Line、Click-to-Show，居中；
3. 右区：点赞和回复筛选滑杆，右对齐。

网格采用 `minmax(0, 1fr) auto minmax(0, 1fr)`，保证中间布局切换器位于控制栏的几何中心，而不是位于左右控件之间的剩余空间中心。

桌面端控制栏内部最大宽度设为约 `1120px` 并整体居中。在 1280×720 视口下，预计控制栏内容距离两侧各保留约 60px 的视觉留白，明显少于当前右侧约 270px 的空白，同时避免控件贴边。

## 响应式边界

- 新规则仅放在 `@media (min-width: 1201px)` 中；
- `<=1200px` 的 flex 换行布局保持现状；
- `<=768px` 的窄屏防溢出规则保持现状；
- 不修改 CommentToggles、布局按钮或滑杆的功能逻辑。

## 验收标准

在 1280×720 下：

- 控制栏为单行；
- 评论开关位于左区，布局切换器位于页面中间，筛选滑杆位于右区；
- 左右两侧均有适度且近似均衡的留白；
- 右侧不再出现约 270px 的大块空白；
- 页面和控制栏均无水平溢出；
- 正文区域宽度、评论中性色、字体和三种评论布局不发生回归。

在 1200px、768px、375px 和 320px 下：

- 继续使用现有响应式布局；
- 页面无新增水平溢出。

## 测试策略

- 在现有 feature flag 回归测试中增加桌面媒体查询、三列网格、最大宽度和三组对齐方式的静态断言；
- 先运行测试观察预期失败，再添加最小 CSS 实现使其通过；
- 在浏览器中验证 1280×720 的实际 computed style、控件位置和水平溢出；
- 复查 1200px、375px 和 320px，确认桌面规则没有影响现有响应式行为；
- 最后运行生产构建。
