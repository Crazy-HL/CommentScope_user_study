# 实验系统恢复原系统评论展示设计

## 1. 背景与目标

当前实验版的 `ArticleRenderer` 使用了简化的标题、纯文本正文和评论卡片，导致参与者看到的文章与评论外观、段落结构和交互方式明显不同于原系统。

本次改造目标是：在不改变实验流程和数据采集要求的前提下，让阅读阶段及允许查看文章的答题阶段使用原系统的文章/评论展示结构；参与者仍然不能自行切换实验条件。

## 2. 已确认的边界

### 参与者可见内容

- 保留原系统的文章标题、文章元信息、段落排版、正文样式、文章统计信息和评论展示样式。
- 保留四种原系统评论布局的视觉与交互语义：
  - `baseline`：评论集中展示；
  - `cs`：点击正文标记后展开评论；
  - `se`：评论显示在相关句子后；
  - `be`：评论插入正文段落之间。
- 使用 P01–P24 预定义的条件固定布局，不在参与者端提供布局切换。
- 保留评论标记、评论展开/收起、评论点击等行为，并继续上报实验事件。

### 实验约束

- 原系统的研究者控制栏、布局切换按钮、点赞/回复筛选滑杆、评论类型筛选、饼图开关和高频词开关不对参与者显示。
- 实验服务端继续只向参与者返回脱敏后的展示数据；布局条件仍通过不透明的 `render_mode` 传给前端。
- CRA 阶段继续完全隐藏文章和全部评论，不复用文章渲染器。
- ACA、CTIA、评论定位阶段继续显示文章与评论，并使用相同的原系统展示方式。

## 3. 推荐方案：迁移原组件的展示核心，接入实验数据和事件接口

不直接把原系统的 `ArticleContent.vue` 原样挂载到实验流程中，而是提取/迁移其展示核心到实验专用渲染器：

1. 复用原系统的文章结构解析、段落/句子渲染、评论锚点匹配、评论类型颜色和评论卡片样式。
2. 将 `currentLayout` 改为由 `article.render_mode` 单向决定，移除参与者可操作的布局切换。
3. 将原系统依赖的完整文章字段映射到实验材料字段：实验材料缺失的作者、发布时间、更新时间等元数据使用安全的空值/不显示策略，不伪造研究数据。
4. 将原系统的评论字段映射到实验字段：`text`、`like_count`、`reply_count`、`internal_anchor`、`position_band`，必要时在渲染层生成原系统所需的兼容字段。
5. 将原系统交互统一转换为实验的 `interaction` 事件，继续由 `ReadingStage`/`QuestionStage` 记录到 SQLite。
6. 保留实验页面自己的底部“完成阅读并答题”操作条和 CRA 隐藏逻辑。

## 4. 方案比较

### 方案 A（推荐）：实验渲染器兼容原系统视觉核心

- 优点：实验流程、事件接口和 CRA 规则保持稳定；参与者看到的文章/评论最接近原系统；不引入研究者控制功能。
- 缺点：需要整理原系统组件中的数据适配和样式，改造量中等。

### 方案 B：直接嵌入原 `ArticleContent.vue`

- 优点：短期内视觉复用最多。
- 缺点：原组件包含 API 拉取、研究者控制栏、布局切换和筛选状态，难以保证实验条件固定；还可能把实验不应暴露的控制和内部数据带给参与者。

### 方案 C：继续在当前简化渲染器上逐项补样式

- 优点：改动集中在实验目录。
- 缺点：容易只复刻颜色而无法恢复原系统的段落结构、评论锚点、标记和交互语义；后续与原系统继续产生视觉漂移。

选择方案 A，因为它同时满足“与原系统保持一致”和“实验条件不可被参与者改变”两个目标。

## 5. 实现阶段的验收标准

### 视觉与结构

- 阅读阶段的文章标题、元信息、段落结构和正文排版与原系统一致或仅因实验页面容器而有必要差异。
- 四种布局下评论的相对位置、评论标记、评论卡片和统计信息与原系统一致。
- 页面中不出现原系统的研究者控制栏、布局切换按钮、筛选滑杆或调试信息。

### 实验行为

- `render_mode` 决定布局，参与者无法通过 UI 修改布局。
- 评论展开、收起、点击和滚动行为仍产生实验事件。
- CRA 阶段文章正文和评论均不存在于可见 DOM 中。
- ACA、CTIA、评论定位阶段文章和评论可见。

### 回归验证

- 新增静态契约测试，锁定原系统关键结构类名/布局分支以及控制栏隐藏要求。
- 运行服务端全量测试、前端实验流程测试和生产构建。
- 在本地浏览器逐一检查至少一个 `baseline`、`cs`、`se`、`be` 条件，并确认 CRA 阶段仍隐藏内容。

## 6. 不在本次范围内

- 不重新设计原系统的视觉风格。
- 不恢复参与者端的布局切换、筛选和图表控制。
- 不改变文章、评论、题目、分配顺序或 SQLite 数据表结构。
- 不删除正式数据库或之前的完整备份。
