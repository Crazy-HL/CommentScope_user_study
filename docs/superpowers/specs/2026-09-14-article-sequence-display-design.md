# 管理员文章编号与顺序筛选设计

- **日期**：2026-09-14
- **状态**：已确认，待实施
- **关联项目**：CommentScope 实验系统

## 1. 目标

管理员普通总览页和参与者详情页不再直接展示内部文章编号 `A02/A03/A04/A07`，而统一使用研究者易读的展示编号：

| 展示编号 | 内部文章编号 |
| --- | --- |
| 01 | A02 |
| 02 | A03 |
| 03 | A04 |
| 04 | A07 |

同时，文章筛选要区分“完整文章顺序”和“文章在本次参与者实验中的位置”。

## 2. 展示规则

- 管理员界面中的文章下拉框、表格、参与者详情标题和顺序摘要统一显示 `01`、`02`、`03`、`04`。
- 页面不显示原始 `A02/A03/A04/A07`。
- 数据库、API 返回的内部关联字段继续保留真实 `article_id`，避免破坏 SQLite 中已有的文章、题目、回答和事件关联。
- 导出数据不改变既有内部字段；如已有展示编号字段则可同时保留，但本次不重命名原始 `article_id`。

## 3. 筛选器

普通总览页使用三个清晰的筛选器：

### 文章

```text
全部文章
01
02
03
04
```

前端值仍对应内部值 `A02/A03/A04/A07`，只改变显示文本。

### 文章顺序

该筛选器表示参与者完成四篇文章的完整顺序，前端显示：

```text
全部顺序
01 → 02 → 03 → 04
02 → 03 → 04 → 01
03 → 04 → 01 → 02
04 → 01 → 02 → 03
```

API 使用不含空格的稳定值：

```text
01-02-03-04
02-03-04-01
03-04-01-02
04-01-02-03
```

后端将序列映射到现有实验分组：

```text
01-02-03-04 -> G1
02-03-04-01 -> G2
03-04-01-02 -> G3
04-01-02-03 -> G4
```

筛选按 `sessions.group_id` 实现，因此能同时影响参与者列表和文章区块统计。

### 文章位置

该筛选器表示文章在本次参与者流程中处于第几个位置，前端显示：

```text
全部位置
01
02
03
04
```

API 仍使用 `article_order=1/2/3/4`，只改变页面文案，避免与完整顺序筛选混淆。

## 4. 参与者详情行为

当选择 `participant_id` 时，详情区域必须重新按参与者编号单独加载完整记录：

- 四篇文章区块；
- 四篇文章的全部逐题回答；
- 评论交互事件；
- 主观评价；
- 偏好排序与理由；
- 访谈回答。

其它筛选条件可以继续影响总览统计，但不得截断参与者详情。

## 5. 校验与兼容

- 后端拒绝不在四个合法序列中的 `article_sequence`。
- 现有 `article_order` 的 1–4 校验继续保留。
- 现有 `article_id` 的内部校验继续保留。
- 空序列表示不筛选。
- 不增加 `mode = pilot`，不改变实验流程，也不写入模拟数据。

## 6. 验收标准

1. 普通总览页不出现 `A02/A03/A04/A07` 作为用户可见文章标签。
2. 文章筛选显示 `01–04`，并能正确映射到内部文章。
3. 文章顺序筛选提供且仅提供四个完整顺序组合。
4. 文章位置筛选提供 `01–04`，并能正确筛选 `article_order`。
5. 选择任一合法顺序后，统计范围对应正确的实验分组。
6. 非法顺序请求返回校验错误。
7. 选择参与者后，详情仍显示该参与者的四篇文章完整数据。
